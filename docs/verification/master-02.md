# Master 02 / 36 — building categories and live prerequisites

Game version remains `0.1.0`; save schema remains `7`. Availability is derived from the world, with no separately saved unlock list.

## Implemented phases

- **A — Categories:** the existing Object Registry retains its object category `building` and now owns each building's `buildingCategory`. The Buildings bar reads it to show All, Castle & Defense, Housing, Food & Farming, Mining & Industry, Logistics & Trade and Infrastructure. Only actual registered buildings appear. Housing/Infrastructure are intentionally empty until their later stages. Data-only extensions join their category automatically; uncategorized extensions stay in All. Mobile tabs scroll horizontally; changing category cancels an incompatible preview without disabling camera keys.
- **B — Requirements:** registry-owned `requiresCompletedBuildings` and `unlockDescription`, validated for real building IDs, duplicates and cycles. The single BuildingUnlockManager updates its UI index on building-world events, registry changes and load, rather than every rendered frame. New placement independently checks the current world before payment, reservations or occupancy. Starting Castle grants no farming prerequisite. Granary is initially available; completed Granary permits Farmhouse; completed Farmhouse permits Wheat Field and Orchard. No new restrictions on Mill, Bakery or Hunting Lodge.
- **C — Integration:** disabled build buttons retain visible grayed previews, lock labels, prices, footprints and explanatory tooltips. Pending prerequisites explicitly require completion. Asset Library shows the registry category and static unlock requirements/descriptions without becoming a construction interface. Construction completion/cancellation and load emit the shared world-change event. Already existing structures are untouched, and a previously valid blueprint may finish after losing its prerequisite. Load re-derives availability from actual completed buildings; no save bump is necessary.
