## Implementation decisions
- Fog edge: the terrain keeps painting each tile visible / remembered / unknown (chunk canvases, unchanged). The new layer only darkens the *visible* side of the border, so the per-tile step turns into a gradient that ends at the look of the neighbouring tile: toward unknown ground it fades to black, toward remembered ground to a dark grey near the memory look (`memoryGrey × brightness`, alpha `1 − (memoryBrightness + edgeBrightness/2)`), so the player's memory-brightness setting is respected.
- The mask is built in grid space (4 px per tile, 2 px when the region is over 3000 tiles, e.g. zoomed far out), with a two-pass chamfer distance (1, √2) to the nearest unseen pixel and a smoothstep falloff over `width` = 1.5 tiles. It is drawn with one image inside a container: container scale (64/√2, 32/√2) after a 45° child rotation equals `gridToWorld` exactly, so no screen-space canvas is needed and it works in both Canvas and WebGL renderers (both checked).
- Bilinear filtering ramps between pixel centres, which left a bright rim on the visible side of the border; unseen pixels touching the edge now take the edge darkness ("dilation"), so the ramp falls on the unseen side. NEAREST filtering at 8 px/tile was tried and rejected: visible banding, and 4× the build cost.
- Rebuilds: only when the fog revision, memory brightness, exploration mode or the camera box (snapped to 4 tiles, + 3 tile margin, clipped to the sight bounds) change, and at most every 60 ms. Buffers are allocated once.
- Fish: a fixed hash per tile decides whether that tile has a fish (chance by stock state × depth: deep 1, shallow 0.6; fords and land none), so fish don't flicker or jump when the camera moves; the lowest normalized hashes win when more than 32 tiles qualify. Targets refresh 4× a second; the fog check runs every frame so a fish disappears the moment its tile leaves sight. Shadows are a small iso-projected teardrop texture in 8 headings (canvas, generated once), alpha ≈ 0.3; ripples are pooled flattened ellipses. Fish swim while the game is paused (decoration only).
- Marketplace: the fix is in the game's merge of approved art, not in the Studio export. The export itself is slightly off (not edited, `studio/` untouched): `base.y` = 114, but the paved square's bottom vertex is at y = 110, and the square is drawn at ~94 % of the 3 × 3 diamond (181 × 90 px instead of 192 × 96). So the square's front tip sits 4 px above the footprint's front corner and a thin rim of the footprint shows around it. A future Studio re-export of `marketplace-square` should fix the base and size; the game will pick it up through `npm run studio:sync`.

## Testing

- Performance (headless Chromium, Canvas renderer, 1440 × 900, zoom 1, Fog on, a test sight source moving every frame so the mask rebuilds at the 60 ms cap, ~14 builds/s — worst case; 3 × 8 s off / on alternating): fog edge 0.16–0.18 ms per frame on average (mask build 0.58–0.65 ms for ~16 000 px), fish 0.02–0.03 ms per frame (5–7 fish) — together ≈ 1.2 % of a 16.7 ms frame. Measured FPS 59.2 (off) vs 58.7 (on) average, −0.7 %, inside the run-to-run noise (whole-frame CPU averages 3.67 ms off vs 3.45 ms on, also noise). Node micro-benchmark of `fogEdgeMask`: 40 × 30 tiles @4 px 0.31 ms, 54 × 54 @4 px 0.68 ms, 108 × 108 @2 px 0.79 ms. The first try (8 px/tile) cost 2.1 ms per build, ~3.5 % FPS, and was dropped.
